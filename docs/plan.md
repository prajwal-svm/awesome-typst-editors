# Awesome Typst Editors implementation plan

Work through the tasks in order. Steps use checkboxes (`- [ ]`) for tracking. Every task's requirements include the Global Constraints below.

**Goal:** A Typst-built, $0 site that celebrates every Typst editor with the same card, GitHub-backed hearts and comments, and a generated awesome-style README.

**Architecture:** One Typst bundle compile (`site/main.typ`) writes every HTML page, the PNG social images, `sitemap.xml` and `README.md`. Typst can't reach the network, so two small bash scripts (`gh` + `jq`) create the per-editor GitHub Discussions and fetch stars, licenses and heart/comment counts into `data/generated.json` before the compile. A GitHub Actions workflow runs both hourly and deploys to GitHub Pages.

**Tech Stack:** Typst 0.15.1 (bundle + HTML export), bash, `gh`, `jq`, GitHub Pages / Actions / Discussions, giscus.

**Spec:** `docs/design.md` (mockups in `docs/mockups/`). Read it with this plan.

## Global Constraints

- Typst 0.15.1. Build command: `typst compile site/main.typ _site --format bundle --features bundle,html --root .` plus `--input` values. Tests use the same flags.
- `typst query` is deprecated in 0.15.1. Use `typst eval '<expr>' --root . --format json`, and `typst eval 'query(<label>).first().value' --in <file> --root . --format json` to read labelled metadata.
- Typst reads YAML dates such as `2026-07-05` as strings. Parse them by hand.
- Repo `prajwal-svm/awesome-typst-editors`, public. Site URL `https://prajwal-svm.github.io/awesome-typst-editors/`. Base path `/awesome-typst-editors/`. License CC0 1.0.
- Discussion category `Editors`, announcement format. giscus settings: `data-mapping="specific"`, `data-term=<slug>`, `data-strict="1"`, `data-reactions-enabled="1"`, `data-input-position="top"`, `data-theme="preferred_color_scheme"`, `data-loading="lazy"`, `data-lang="en"`.
- giscus strict matching: a discussion's title is the slug, and its body ends with `\n\n<!-- sha1: <lowercase hex SHA-1 of the slug> -->`.
- Inclusion: the site shows an editor when `arrived <= today - 30 days`. The README also needs `stars >= 50`.
- Kinds, in this fixed order: `desktop`, `web`, `mobile`, `terminal`. Labels: Desktop, Web, Mobile, Terminal.
- Nothing is ever sorted, totalled or labelled by hearts.
- No CSS outline or focus ring anywhere. Show focus with a background tint or a border colour change.
- No co-author or tool attribution lines, and no AI tool names, anywhere in the repo or in commit messages.
- Stage files by explicit path. Never `git add -A`, `git add .` or `git commit -a`. Run `git status --short` before and `git diff --cached --stat` after staging.
- Every user-facing string lives in `site/lib/copy.typ` and gets a plain-language copy pass before launch.
- Workflow action versions: `actions/checkout@v7`, `typst-community/setup-typst@v5` with `typst-version: 0.15.1`, `actions/upload-pages-artifact@v5`, `actions/deploy-pages@v5`. Runner `ubuntu-24.04`.
- Crons: site build `17 * * * *`, counter check `23 6 * * 1`.
- Counter data URL: `https://raw.githubusercontent.com/sermuns/days-since-last-typst-editor/main/data.csv`.
- No custom domain, no paid services.

## Review Focus

1. A name or description containing `&`, `<`, quotes, square brackets or non-ASCII letters must render literally in HTML text, attributes, JSON-LD and README links. Tests: Task 2 (card HTML), Task 3 (attributes and JSON-LD), Task 4 (README link text).
2. An editor with no description, builder, source, homepage or links must still get a clean card and page: no `none` text and no empty links. Tests: Tasks 2 and 3, using the `bramble` fixture.
3. Bad data (a duplicate slug, an unknown kind, a missing or malformed date, a bad slug) must stop the build with a message that names the editor. Nothing gets published half-broken. Test: Task 1.
4. A GitHub API error or rate limit must fail the build before deploy, so the live site keeps its last good counts instead of showing zeros. Tests: Task 5 (the script exits non-zero with empty stdout) and Task 8 (the workflow fetches before it compiles, under `set -euo pipefail`).
5. Running the discussion step every hour must never create duplicates, and discussions in other categories must not count. Test: Task 6.

### Task 1: Repo skeleton, test runner and data rules

**Interfaces:**
- Produces, in `site/lib/data.typ`:

  - `editors`: an array of dicts with keys `name, slug, arrived (datetime), kinds, platforms, description, builder, source, homepage, forum, reddit, stars, license, open-source (bool), hearts (int), comments (int), discussion-url`. Missing optional values are `none`, missing lists are `()`, missing counts are `0`.

  - `by-name(list)`, `by-arrival(list)` (newest first, ties by name), `by-kind(list) -> array of (kind: str, editors: array)` (fixed order, non-empty only).
  - `iso(d) -> "2026-09-17"`, `day-label(d) -> "17 Sep 2026"`, `month-label(d) -> "September 2026"`.
  - `repo-id`, `category-id` (str or none).

- [ ] **Step 2: Write the fixtures and the failing data tests**

`tests/query-data.typ` imports `/site/lib/data.typ` and places `#metadata((site:, readme:, az:, timeline:, kinds:, open:, hearts:, desc:, builder:, stars:)) <result>`, with slugs as arrays and per-slug dicts. `tests/test_data.sh` reads it with `typst eval 'query(<result>).first().value' --in tests/query-data.typ --root . --format json $FIXTURE_INPUTS` and asserts with `jq`:

```bash
assert_eq "$(jq -c .site <<<"$R")"     '["aurora","bramble","delta","echo","foxglove"]'
assert_eq "$(jq -c .readme <<<"$R")"   '["aurora","echo","foxglove"]'

assert_eq "$(jq -c '[.kinds[].kind]' <<<"$R")" '["desktop","web","terminal"]'
assert_eq "$(jq -c '.kinds[1].editors' <<<"$R")" '["bramble","echo","foxglove"]'
assert_eq "$(jq -c .open <<<"$R")"     '["aurora","foxglove"]'
assert_eq "$(jq -r .desc.echo <<<"$R")"  'Edits Typst in two places at once'   # YAML wins
assert_eq "$(jq -r .builder.aurora <<<"$R")" 'example'                         # fetched owner
assert_eq "$(jq -r .stars.foxglove <<<"$R")" '75'                              # YAML stars
assert_eq "$(jq -r .hearts.bramble <<<"$R")" '0'                               # no discussion
```

Also check that `az` doesn't change when `foxglove` has the most hearts, and that a build with no `generated` input still gives `site` with all counts at 0. Each bad fixture must fail with a message naming the slug: `duplicate slug "aurora"`, `unknown kind "tablet" for "aurora"`, `"aurora" is missing arrived`, `bad date "2026-13-40" for "aurora"`, `bad slug "Aurora Editor"`.

### Task 5: Fetch script

**Files:**
- Create: `scripts/lib.sh`, `scripts/fetch-data.sh`, `tests/stubs/gh`, `tests/stubs/curl`, `tests/fixtures/api/` (`repos_example_aurora.json`, `repos_example_cinder.json`, `repos_example_echo.json`, `codeberg_example_delta.json`, `graphql_discussions.json`, `graphql_discussions_more.json`), `tests/test_fetch.sh`

**Interfaces:**
- Produces, in `scripts/lib.sh` (sourced, `set -euo pipefail`):
  - `editors_json [data_path]` prints the YAML as JSON via `typst eval "yaml(\"$data_path\")" --root . --format json` (default `/data/editors.yaml`).
  - `github_repo url` prints `owner/repo` for `https://github.com/<o>/<r>[/...]`, or nothing.
  - `codeberg_repo url` does the same for codeberg.org.
  - `sha1_hex text` prints a lowercase SHA-1, using `sha1sum` if present, else `shasum -a 1`.
  - `discussions_json repo` prints a single GraphQL response: the repository `id`, `discussionCategories(first: 25) { nodes { id name } }` and `discussions(first: 100) { pageInfo { hasNextPage } nodes { title number url category { name } reactionGroups { content reactors { totalCount } } comments { totalCount } } }`. It exits 1 if `hasNextPage` is true, with the message `more than 100 discussions: add pagination`.
- `scripts/fetch-data.sh` reads env `REPO` (default `prajwal-svm/awesome-typst-editors`), `CATEGORY` (default `Editors`) and `DATA` (default `/data/editors.yaml`), and prints the generated JSON in the shape of `tests/fixtures/generated.json`. It calls `gh api repos/<o>/<r>` for GitHub sources and `curl -fsS https://codeberg.org/api/v1/repos/<o>/<r>` for Codeberg sources (`stars_count`, `description`, `owner.login`; license null), and skips every other host. `hearts` is the `totalCount` of the `HEART` reaction group (0 if absent). Only discussions in `CATEGORY` count, keyed by title. On any failed call it exits 1 with nothing on stdout: build the JSON in a variable and print it only at the end.
- `tests/stubs/gh` serves `repos/<o>/<r>` from `tests/fixtures/api/repos_<o>_<r>.json` and `graphql` from `$STUB_GRAPHQL` (a fixture path). For `createDiscussion` mutations it appends the `-f` arguments to `$STUB_LOG` and prints `{"data":{"createDiscussion":{"discussion":{"number":9,"url":"u"}}}}`. It exits 1 when its arguments contain `$STUB_FAIL_ON`, or when a fixture is missing. `tests/stubs/curl` does the same for Codeberg URLs.

Concurrency group `pages`, `cancel-in-progress: false`. A `build` job on `ubuntu-24.04` runs these steps in order, each `run` under `set -euo pipefail` with `GH_TOKEN: ${{ github.token }}`:
  1. checkout
  2. setup-typst 0.15.1
  3. `bash tests/run.sh`

  6. `typst compile site/main.typ _site --format bundle --features bundle,html --root . --input generated=/data/generated.json --input today="$(date -u +%F)"`
  7. "Commit README if changed" (block below)
  8. `actions/upload-pages-artifact@v5` with `path: _site`

  A `deploy` job (`needs: build`, environment `github-pages`, url `${{ steps.deployment.outputs.page_url }}`) runs `actions/deploy-pages@v5`.

"Commit README if changed" run block. Use `git status --porcelain`, because `git diff --quiet` misses an untracked README on the first run:

```bash
mv _site/README.md README.md
if [ -z "$(git status --porcelain -- README.md)" ]; then
  echo "README unchanged"
else
  git config user.name "github-actions[bot]"
  git config user.email "41898282+github-actions[bot]@users.noreply.github.com"
  git add README.md
  git commit -m "docs: regenerate README"
  git pull --rebase
  git push
fi
```
